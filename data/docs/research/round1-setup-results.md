# 라운드 1 — 간단 과제 (소셜 Todo 웹앱)

동일한 요구사항서(PRD)를 5개 파이프라인에 투입한 1차 벤치마크. 이 난이도에서는 전 케이스가 품질 상한(98~100점)에 도달해, 변별은 비용과 시간에서 갈렸다.

## 01. 실험 설계

PRD는 기능 요구 21개(FR-1~21: 인증, 인가, Todo CRUD, 친구 관계, UI 5종)와 비기능 요구 3개(NFR: 무크래시, 코드 품질, 영속성)로 구성했고, 공정성을 위해 기술 스택을 고정했다(Node.js 표준 라이브러리 전용, `node server.js` 단일 진입점, JSON 파일 영속성, 정적 프런트엔드).

### 케이스 설계

| 케이스 | 전략 | 파이프라인 | 에이전트 수 |
|---|---|---|---|
| case1 | 하네스 엔지니어링 | Opus5 기획·설계·개발 전부 단독 | 1 |
| case2 | Agentic · 설계 가중 | Opus5 기획/설계 → Sonnet5 풀스택 개발 | 2 |
| case2_1 | Agentic · 개발 가중 | Sonnet5 기획/설계 → Opus5 풀스택 개발 | 2 |
| case3 | Agentic FE/BE · 설계 가중 | Opus5 기획/설계 → Sonnet5 FE + BE 병렬 | 3 |
| case3_1 | Agentic FE/BE · 개발 가중 | Sonnet5 기획/설계 → Opus5 FE + BE 병렬 | 3 |

### 격리와 공정성 통제

각 에이전트는 자기 케이스 디렉토리와 PRD 파일만 접근할 수 있다. 다른 케이스 디렉토리·평가 디렉토리 접근은 프롬프트로 금지했다. 평가 루브릭은 PRD만 읽도록 격리된 별도 에이전트가 개발과 동시에 독립 작성해, 평가 기준이 개발 단계로 유출될 경로를 차단했다. FE/BE 병렬 케이스는 파일 소유권을 분리(`public/`은 FE 전용, 나머지는 BE 전용)해 충돌 없이 동시 작업하게 했다.

### 측정 방법

토큰은 각 에이전트 트랜스크립트(JSONL)의 assistant 메시지 usage를 message ID 기준 중복 제거 후 합산했다(input / output / cache read / cache write를 5분·1시간 TTL까지 구분). 비용은 Anthropic 정가 기준이며 캐시 읽기 0.1×, 캐시 쓰기(5분 TTL) 1.25× 배율을 적용했다. Sonnet5 프로모션 단가($2/$10, ~2026-08-31) 적용 수치는 별도 병기한다.

## 02. 종합 결과

| 케이스 | 품질 점수 | 순수 개발 비용 | 프로모션가 | 100점당 비용 | output 토큰 | 파이프라인 시간 | 코드 규모 |
|---|---|---|---|---|---|---|---|
| case3 (최고 효율) | 98 | $5.03 | $3.70 | $5.13 | 72.7k | 19.9분* | 3,157줄 |
| case2_1 | 100 | $5.83 | $5.64 | $5.83 | 62.3k | 19.8분 | 2,530줄 |
| case3_1 | 100 | $7.37 | $7.22 | $7.37 | 105.5k | 19.6분 | 3,965줄 |
| case2 | 100 | $8.72 | $6.38 | $8.72 | 98.8k | 27.2분 | 3,095줄 |
| case1 | 100 | $10.95 | $10.95 | $10.95 | 72.9k | 27.0분 | 2,398줄 |

\* case3의 시간은 인프라 오류(API 연결 끊김)로 인한 백엔드 재시도를 제외한 논리적 파이프라인 시간. 재시도 포함 실제 wall-clock은 39.7분. 품질 점수는 감사(교차 검증) 조정 반영 확정치. 100점당 비용 = 순수 개발 비용 ÷ 점수 × 100. 코드 규모는 data/ 제외 JS·HTML·CSS 합계.

## 라운드 1 한 줄 결론

이 난이도의 과제에서 품질은 파이프라인을 가리지 않았다(감사 확정 98~100점). 승부는 비용과 시간에서 갈렸고, **"Opus 설계 → Sonnet 분업 개발"(case3, 100점 환산 $5.13)**과 **"Sonnet 설계 → Opus 단독 개발"(case2_1, $5.83)**이 최적이었다. 가장 비싼 방법은 최상위 모델 하나에게 전부 맡기는 것(case1, $10.95)이었다 — 품질 이득은 없었다. 최고 효율 대비 최저 효율(case1)의 격차는 **2.13배**.
